- **UPnP-Fallstrick (2026-09-22):** Die Fritz!Box ueberschreibt eine vorhandene IPv4-Weiterleitung NICHT; `AddPortMapping` antwortet mit Fehler 718. `mc-pinholes.py` wertete 718 als Erfolg, dadurch zeigte 10478 noch auf einen alten internen Port und der Server war von aussen tot. Jetzt: bei 718 erst `DeletePortMapping`, dann neu anlegen (Backup `mc-pinholes.py.vor-718fix`). Ausserdem vergibt die Box bei DS-Lite jeden externen Port nur EINMAL, protokolluebergreifend: TCP 10477 ist blockiert, weil UDP 10477 fuer Bedrock belegt ist.

**Why:** Der Anschluss hat **kein eigenes öffentliches IPv4** (DS-Lite/Port-Sharing): extern sind nur die Ports **10476–10495** nutzbar, UPnP lehnt alle anderen mit Fehler 718 ab. DuckDNS kann kein SRV, portfrei geht also nur über IPv6. **Die öffentliche IPv4 wechselt bei jeder Neueinwahl** (z. B. 94.134.94.254 → 94.134.95.86), und dabei verliert die Fritz!Box auch die IPv4-UPnP-Weiterleitungen.
**How to apply:** Zugang — **IPv6 portfrei**: `l0rdr3spawn.duckdns.org` (Java 25565, Bedrock 19132). **IPv4**: `l0rdr3spawn.duckdns.org:10476` (Java) bzw. Port 10477 (Bedrock). Freigaben passwortfrei per UPnP: IPv4 über `http://192.168.178.1:49000/igdupnp/control/WANIPConn1`, IPv6-Pinholes über `/igd2upnp/control/WANIPv6Firewall1`. **Selbstheilung**: `/home/luis/mc-net-refresh.sh` (Cron alle 10 Min) + `/home/luis/mc-pinholes.py` erneuern DuckDNS A+AAAA sowie IPv4-Weiterleitungen und IPv6-Pinholes. **Fallstrick:** Beim DuckDNS-Update müssen `ip=` UND `ipv6=` ausdrücklich gesetzt werden — sonst sieht DuckDNS nur die IPv6-Absenderadresse und der A-Eintrag veraltet unbemerkt.
